# P7 — Frontend: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Una aplicación web con la que una empresa se da de alta como emisor, carga su certificado, mantiene clientes y productos, emite facturas (con borradores), sigue su estado ante el SRI y descarga el XML y el RIDE.

**Architecture:** Next.js (App Router) en `/frontend`, con el patrón *backend for frontend*: el navegador nunca ve los tokens. El servidor de Next hace el inicio de sesión OIDC (código de autorización con PKCE), guarda la sesión cifrada en cookies `httpOnly` y expone un único proxy `/api/backend/*` que añade el `Authorization` y la empresa activa antes de llamar a la API de Spring. Las pantallas son componentes de cliente que usan un cliente tipado generado del contrato OpenAPI.

**Tech Stack:** Next.js 16.4, React 19, TypeScript 5.9, `openapi-typescript` + `openapi-fetch` (cliente tipado), `openid-client` 6 (OIDC), `jose` (cifrado de la sesión), Vitest 5 + Testing Library + jsdom, ESLint. CSS propio con variables (sin biblioteca de componentes). Keycloak solo como proveedor OIDC de desarrollo.

**Spec:** [docs/01-product-requirements.md](../../01-product-requirements.md) (PR-01 a PR-09), [docs/11-api-specification.md](../../11-api-specification.md), [contracts/openapi.yaml](../../../contracts/openapi.yaml) v0.6.0, [docs/10-security.md](../../10-security.md), [docs/DEVELOPMENT.md](../../DEVELOPMENT.md) (Etapa 7).

## Global Constraints

- El navegador no recibe nunca el token de acceso ni el de refresco: viven solo en cookies cifradas `httpOnly`, `SameSite=Lax`, `Secure` fuera de desarrollo.
- El proxy solo reenvía a `${API_BASE_URL}/api/v1/…`; nunca a una dirección tomada de la petición. Rechaza rutas con `..`, `//` o caracteres de control.
- Toda petición que cambia datos (`POST`, `PUT`, `PATCH`, `DELETE`) al proxy debe venir del mismo origen (`Sec-Fetch-Site: same-origin`, o `Origin` igual al propio) y llevar la cabecera `X-Requested-With: einvoice-web`; si no, `403`.
- El certificado `.p12` y su contraseña pasan del formulario al proxy y de ahí a la API: no se guardan en `localStorage`, ni en el estado global, ni en logs; el campo se vacía tras enviar.
- Los importes se manejan como cadenas decimales, nunca como `number`. El total que vale es el del servidor; el del editor es una vista previa.
- Los tipos de la API salen solo de `contracts/openapi.yaml`; `src/api/schema.ts` se genera y una prueba falla si está desactualizado.
- Textos de la interfaz en español; código en inglés. Interfaz utilizable con teclado, con etiquetas en todos los campos y sin depender solo del color para el estado.
- La interfaz oculta lo que el rol no puede hacer, pero la autorización real es la del servidor.
- Sin telemetría, fuentes ni scripts de terceros. `next telemetry` desactivada en los scripts.
- Comandos desde `/frontend`: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`.

## Decisiones de diseño

- **Borradores en el navegador.** La API no tiene estado `DRAFT`: un borrador es un formulario guardado en `localStorage`, por empresa. No se comparten entre dispositivos y no reservan secuencial.
- **Empresa activa** en una cookie no sensible (`einvoice_tenant`); el proxy la envía como `X-Tenant-Id`.
- **Monitor por sondeo.** La lista y el detalle se refrescan cada 5 segundos mientras haya comprobantes en un estado no final. Sin websockets.
- **Sin pruebas con navegador automatizado en el repositorio** (Playwright descargaría navegadores). La verificación de extremo a extremo se hace a mano con el navegador integrado contra la API real y un Keycloak local, y queda descrita paso a paso.
- **Proveedor OIDC de desarrollo:** Keycloak en `infra/docker-compose.yml` bajo el perfil `idp`, con un reino importado (`infra/keycloak/einvoice-realm.json`) que trae el cliente web, la audiencia `einvoice-api` y un usuario de demostración. No es una elección para producción.

## Review Focus

1. **Petición de otro sitio al proxy** (CSRF) → `403`, sin llegar a la API (Task 2).
2. **Ruta maliciosa en el proxy** (`/api/backend/../../actuator`, URL absoluta, doble barra) → `400`, sin petición saliente (Task 2).
3. **Sesión caducada o token rechazado** → se renueva con el token de refresco; si no se puede, la interfaz lleva a iniciar sesión sin perder el borrador (Task 2 y Task 5).
4. **Doble clic en "Emitir"** → una sola factura: la clave de idempotencia nace con el borrador y se reutiliza en cada reintento (Task 5).
5. **Errores de la API** (`422` con `errorCode`, `409`, caída) → mensaje comprensible en español junto al formulario, nunca una pantalla en blanco (Task 3 a 6).
